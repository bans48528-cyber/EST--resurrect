# EST OS 下位机菜单开发提示词

请接手 EST 下位机的设备端菜单实现。目标是在不破坏现有电机、MicroPython、USB、传感器和程序槽位能力的前提下，把已经冻结的 EST OS 首版菜单设计接入正式固件。

## 首版冻结范围

- 180 x 128 单色 LCD。
- 六个实体键固定为 `KEY0=返回`、`KEY1=左`、`KEY2=上`、`KEY3=下`、`KEY4=右`、`KEY5=确认`。
- 返回和确认位于上排，四个方向键位于下方。
- 主菜单横向显示四项：最近 `.py` 程序、`Programs`、`Ports`、`Settings`。
- 第一项默认选中，确认键直接运行最近下载或最近运行的程序；没有最近程序时显示对应空状态且确认键无操作。
- `Programs` 显示槽位 `0..7`，确认运行，右键打开删除确认；删除弹窗默认取消并使用左右键选择。
- 运行页面只有 `RUNNING`，不提供暂停，不识别 `HOLD OK PAUSE`；确认键和方向键继续交给用户程序。
- 运行期间短按返回立即终止用户程序和全部马达并回主菜单，不显示停止确认。
- 主菜单短按返回打开关机确认；弹窗没有选中项，返回键取消，确认键关机，左右键无操作。
- `Ports` 在同一页上方显示马达 `A..D`，下方显示传感器 `1..4`；上下切换分区，左右切换当前分区端口，确认键无操作。
- `Settings` 包含背光 `10%..100%`、音量 `0%..100%`、语言、设备信息；背光和音量按 `10%` 步进调整。
- 设备信息从设置进入，返回时先回设置。
- 首版必须同时实现中文与 English，首次启动默认中文。所有菜单、弹窗、状态和错误信息使用集中式双语资源并可即时切换。只有开发构建确实没有中文字库时才允许临时回退 English，该构建不能算首版验收通过。
- 首页使用 `docs/assets/menu_icons/` 内的四个 32 x 32 单色图标；反白区固定短高度、垂直中线一致，文字紧贴图标下方。

## 异常状态必须实现

1. 无最近程序：显示“暂无最近程序”，确认键无操作；成功运行后立即建立最近项。
2. Flash 或槽位列表读取失败：不得显示缓存旧列表；显示稳定错误码，确认键重试，返回键回主菜单。
3. 程序文件损坏：不得运行；显示错误信息和稳定错误码，确认键或返回键回程序列表。
4. 程序运行异常：先终止用户程序并停止全部马达，再显示“程序已停止 / 马达已安全停止”和稳定错误码；确认键或返回键回程序列表。
5. 端口识别中：显示“识别中 / 检测中”，尚未有效的数据统一显示 `--`，端口导航保持可用。
6. 设备拔出：立即显示“未连接”，状态和值改为 `--`，不得继续显示旧数据。
7. 临界低电量：状态栏显示低电量和百分比；禁止启动新程序和新马达任务，显示充电提示，返回键回主菜单。

## 必须先分析并形成结论的固件问题

### 真实关机

检查电源电路、主控低功耗/复位能力、现有板级 API 和 Bootloader 约束，明确设备能否由软件真正断电。给出安全清理顺序，包括用户程序、全部马达、待写配置、LCD、USB 和中断/调度状态。说明确认关机后的最终状态是物理断电、待机、深度睡眠还是安全停机等待重新上电。不要用只显示 `POWER OFF` 的假关机代替结论。

### 设置与最近程序持久化

检查已有配置区、W25Q256 文件系统、程序槽位元数据和写入接口，提出背光、音量、语言及最近程序的持久化方案。必须说明数据格式和版本、写入时机、写放大与磨损控制、掉电恢复、CRC/损坏回退、无效最近程序清理及出厂默认值。形成结论后再实现，不要另建与现有存储服务重复的私有格式。

### 低电量阈值

根据现有电池采样精度、负载压降和马达安全要求，确定禁止启动新程序/马达任务的阈值及恢复滞回。低电量不得影响 STOP、安全清理、USB 和菜单返回操作。

## 推荐代码边界

- `est_ui_state`：非阻塞页面状态机和页面切换。
- `est_ui_renderer`：只绘制当前状态，不直接访问硬件细节。
- `est_key_events`：统一消抖、按下、松开、短按和长按。
- `est_ui_programs`：程序列表、最近程序、运行、停止、删除和错误适配。
- `est_ui_ports`：马达与传感器只读摘要及断开/识别中状态。
- `est_ui_settings`：设置、设备信息及持久化适配。
- 集中式中英文文本资源和中文字库。

同一时间只能有一个 LCD refresh 所有者。至少区分菜单、用户程序、升级和维护屏幕所有权。菜单以约 10 至 20 ms 的非阻塞 tick 运行，不得阻塞 USB、马达控制、传感器、系统 tick 或 MicroPython 服务。菜单只能调用已有或明确新增的 EST C 服务层，不得从页面代码直接操作 GPIO、PWM、外部 Flash 或 MicroPython 内部结构。

按键层必须避免长短按重复触发：长按返回一旦触发紧急停止，松开时不得再发出短按返回，尤其不能回到主菜单后误弹关机确认。

## 工作顺序

1. 输出当前基线、未提交修改、LCD 所有权、按键扫描、主循环挂钩、程序槽位 API、STOP 清理路径、字体/位图能力和配置存储能力的检查结果。
2. 输出真实关机、设置/最近程序持久化和低电量阈值三个问题的分析结论或明确待实机确认项。
3. 给出准确到文件和函数的实现落点、风险与版本切分。
4. 若基线适合开发，继续完成菜单内核、双语资源、按键事件层、首页、Programs、Ports、Settings、Device Info 和异常状态，不停留在方案阶段。
5. 接入程序运行/停止/删除，并复用现有统一安全清理路径。
6. 增加聚焦测试，先跑主机侧测试，再构建固件；有硬件时执行实屏、实体键、程序 STOP、端口拔插和低电量实机验收。
7. 更新开发上下文，记录已实现范围、实测结果、未决问题和下一版本入口。

## 验收底线

- 中文与 English 同版本完整可用，切换后当前页面立即刷新。
- 所有页面在 180 x 128 上无文本重叠、越界或旧数据残留。
- 六键无重复跳项，长按返回不产生后续短按。
- 运行页返回直接停止，确认键和方向键不被系统菜单吞掉。
- 主菜单关机弹窗只响应返回取消和确认关机。
- 删除仍需二次确认且默认取消。
- Flash 错误、程序异常、无最近程序、识别中、拔出和低电量行为符合冻结规则。
- 菜单运行期间 USB、马达闭环、传感器、MicroPython 和系统 tick 保持正常。
- 不破坏当前已验收的电机、HOLD、零速、低速、字体、图片、程序槽位和无限运行契约。

最终请报告：改动文件、核心状态机、三项固件决策、测试/构建结果、未执行的实机项目和残余风险。
