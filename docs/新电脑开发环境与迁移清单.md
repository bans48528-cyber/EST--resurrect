更新日期：2026-08-28

这份文件用于换电脑后直接继续开发，避免重新猜测已经确认过的引导、协议、引脚和硬件结论。

当前活动开发仓库已经迁移到 `D:\EST\EST--resurrect`。原 `D:\BaiduSyncdisk\2026\8月\EST重构` 只保留作历史备份和大型资料入口，不再在其中执行 Git 开发；2026-08-27 已确认百度同步目录中的 Git pack 大量损坏，因此活动 `.git` 必须留在非网盘目录。

## 1. 项目方向不能改变

- 保留主板原有 `03.00B` Bootloader，不修改引导。
- 抛弃无法维护的旧主固件和旧上位机，后续产品固件由本仓库的全新代码发展而来。
- 当前新固件是 **GNU Arm GCC 工程，不需要 Keil**。Keil/ARMCC 只与历史官方工程有关，不是继续开发新固件的必需工具。
- 新固件必须一直保持旧引导升级兼容，让客户不拆机即可升级。
- 长线目标是参考 Pybricks 的分层方式，逐步形成稳定的底层驱动、设备服务和全新上位机接口。

硬件验证阶段的早期 Git 基线提交是 `619d215`；换电脑后应以 GitHub `main` 分支的最新提交为准。

## 4. 必需软件

当前已验证组合：

- Windows 10/11。
- Git for Windows；构建时需要它提供的 `sh`、`mkdir` 等 Unix 工具。
- GNU Arm Toolchain `12.2.1`，标识为 `12.2.MPACBTI-Rel1`。
- GNU Make `4.4.1` 或兼容版本。
- Python `3.12` 或兼容的 Python 3。

升级工具使用 Python 标准库和 Windows HID/SetupAPI，不需要安装额外的 pip 包。工程已经包含固定版本的 libopencm3，commit 为 `2da12dc96e0b9e42a3332348dd9b02a0a17981f8`。MicroPython 从 M0.94A 起使用 Git submodule，固定于官方 `v1.29.0` commit `0fd6c573ea815774668bbb16b8e197c8822368b2`；首次克隆必须执行上面的 submodule 初始化命令。

如果把旧电脑的 `work/toolchains` 复制进新仓库，可以临时设置：

```powershell
$repo = 'D:\EST\EST--resurrect'
$gitRoot = Split-Path (Split-Path (Get-Command git).Source)
$env:PATH = "$repo\work\toolchains\arm-gcc\bin;$repo\work\toolchains\make\bin;$gitRoot\usr\bin;$env:PATH"
arm-none-eabi-gcc --version
make --version
python --version
```

如果 Git 安装在其他位置，把上面的 Git `usr\bin` 改成实际位置。

## 6. 手动构建新版本

```powershell
Set-Location D:\EST\EST--resurrect\firmware\minimal_upgrade_app
make -j4 APP_VERSION=M1.01A all
```

主要产物：

| 文件 | 用途 |
| --- | --- |
| `build/est_minimal_upgrade_app.bin` | 原始 APP，只能由调试器写到 `0x08010000` |
| `build/est_minimal_upgrade_app.app.bin` | `APP=` 加原始 APP，未固定填充的参考包 |
| `build/est_minimal_upgrade_app.upgrade.bin` | 交给旧引导兼容升级工具的 256 KiB 包 |
| `build/est_minimal_upgrade_app.manifest.json` | 版本、地址、长度和 SHA-256 信息 |

不要把原始 `.bin` 交给升级工具，只发送 `.upgrade.bin`。

## 8. 设备检测与升级

以下命令均从仓库根目录执行：

```powershell
python tools/est_hid_sender/est_hid_sender.py ping
python tools/est_hid_sender/est_hid_sender.py device-status
python tools/est_hid_sender/est_hid_sender.py micropython-status
python tools/est_hid_sender/est_hid_sender.py python-run --file tools/est_hid_sender/examples/compute_result.py --timeout-ms 2000
python tools/est_hid_sender/est_hid_sender.py verify --file firmware/releases/M1.01A/est_minimal_upgrade_app_M1.01A.upgrade.bin
python tools/est_hid_sender/est_hid_sender.py flash --file <目标版本.upgrade.bin>
```

升级时必须记住：

- 工具默认核对同名 manifest、目标版本和 SHA-256。
- 同版本重刷或降级会被阻止；确实需要时才使用 `--force`。
- 普通开发升级可以在新 APP 正常开机、USB 已连接时直接发送，不必预先进入旧引导。
- 从正常 APP 升级时，最终 ACK 后 APP 会主动关机；重新开机后由旧引导搬运。
- 发送完成后先自动轮询心跳；检测到用户已经开机就继续验证，等待一段合理时间仍没有设备时再提示人工开机。
- 直接在旧引导模式发送时，当前实物表现为红灯闪烁；搬运显示到 `100%`、灯熄灭后可能不会自动重启，需要人工断电再开机。
- 不要再把“进入升级模式”描述成红蓝交替；红蓝交替是早期新 APP 的启动诊断表现，不是当前旧引导的固定表现。
