## 1. 目标

在现有 `board_*` 硬件驱动之上建立稳定的 `est_*` C 服务层，再由 MicroPython 和后续积木程序调用。实时控制、安全保护和硬件差异留在 C；用户流程、条件判断和动作组合放在 MicroPython。

本清单用于下一阶段开发，不表示下面的接口目前已经全部实现。

## 2. 已确定的架构

```text
STM32 外设和中断
        ↓
board_* 硬件驱动
        ↓
est_* C 服务 API
   ↙              ↘
USB/HID        MicroPython est 模块
                    ↓
               用户程序/积木
```

必须遵守以下边界：

- 电机 PWM、编码器、速度闭环、位置闭环、双电机同步、看门狗、堵转保护和紧急停止在 C 中执行。
- MicroPython 负责动作组合、流程、条件、循环和普通数值比较。
- 灰度 `< 30` 等用户阈值在 MicroPython 或积木程序中处理。
- 触碰识别电压、滤波、防抖等硬件阈值在 C 中处理。
- Python 脚本异常、软重启或垃圾回收不能中断 C 的安全控制任务。
- C 层不能依赖 Python 正常运行才能停止电机。

## 3. 参数与单位

| 参数 | V1 约定 | 归属 |
|---|---|---|
| 电机功率 | `-100～100%`，表示 PWM 驱动力 | C 校验 |
| 电机速度 | `-100～100%`，表示对应电机类型的目标速度 | C 闭环 |
| 电机角度 | 度，当前单次限制 `-3600～3600°` | C 校验与控制 |
| 电机圈数 | `1 圈 = 360°` | MicroPython 换算 |
| 运行时间 | 毫秒 | C 计时 |
| 距离 | 毫米，仅保留诊断接口，不进入最终软件界面 | C API |
| 温度 | `0.1°C` | C API |
| 灰度/环境光/声音 | `0～100` | C 输出，Python 比较 |
| 屏幕 | `180×128` 单色像素 | C 绘图 |
| 电池电压 | 毫伏 | C API |

电机功率和速度不能混用：功率是固定驱动力，不保证实际转速；速度是闭环目标，C 会根据编码器反馈自动调整功率。

- [x] 实现左右电机各自的速度闭环，并在持续定速任务中按编码器进度协调两路速度。

- [ ] 实现加速、匀速、减速轨迹，减少起停打滑。

## 6. MicroPython 接口映射

- [ ] `Motor`：调用单电机 C API。
- [ ] `MotorPair`/`DriveBase`：调用精确双电机 C API。
- [ ] `Sensor` 及颜色、触碰、超声、陀螺、声音、温度、红外类型类。
- [ ] `Display`、`Buttons`、`LED`、`Audio`、`Battery` 和 `Storage`。
- [ ] Python 默认参数只负责易用性，C 仍需再次检查所有范围。
- [ ] `wait=True` 通过轮询 C 状态等待完成，不能用 Python `sleep` 代替 C 计时。

目标调用示例：

```python
motor = Motor("A")
motor.run_time(speed=50, time=1000, stop=Stop.BRAKE)

drive = DriveBase(left="A", right="B", wheel_diameter=56, axle_track=120)
drive.straight(distance=500, speed=50)
drive.turn(angle=90, speed=30)

gray = ColorSensor(1)
if gray.reflection() < 30:
    drive.stop()
```
