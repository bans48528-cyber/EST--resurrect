# EST 新上位机 USB 应用协议 V1

## 目的

本协议供全新固件与全新上位机通信。它继续使用现有 USB HID、VID/PID 和帧格式，并保留旧引导所需的固件升级命令；新功能只通过新增命令扩展。

当前协议版本为 `1.15`。`1.0` 首次随固件 `M0.52A` 提供；`1.1` 增加马达类型识别，`1.2` 随 `M0.62A` 增加类型感知的位置控制，`1.3` 随 `M0.65A` 增加静止类型刷新和持续闭环定速，`1.4` 随 `M0.68A` 增加马达阻抗诊断数据，`1.5` 随 `M0.71A` 增加 pin 5 弱上拉数字状态，`1.6` 随 `M0.75A` 增加双电机角度同步，`1.7` 随 `M0.83A` 增加双电机持续定速，`1.8` 随 `M0.84A` 增加毫米直行诊断，`1.9` 随 `M0.85A` 增加圈/度/秒直行，`1.10` 随 `M0.86A` 将双电机角度同步扩展为不同行程比例同步，`1.11` 随 `M0.87A` 将双电机持续定速扩展为左右独立速度比例同步，`1.12` 随 `M0.88A` 增加 EV3 Classroom 语义的持续转向，`1.13` 随 `M0.90A` 增加按圈数、角度或秒数自动完成的定量转向，`1.14` 随 `M0.94A` 增加 MicroPython 运行状态查询，`1.15` 随 `M0.95A` 增加 RAM Python 程序上传、运行、停止和状态命令。M0.96A 修复脚本运行期间的 USB 主动停止，但不改变协议字节。主版本保持为 1，已有请求格式仍然兼容。

## 不变的外层帧

| 字段 | 长度 | 说明 |
| --- | ---: | --- |
| 帧头 | 1 | 固定 `0x68` |
| 方向 | 1 | 电脑到设备 `0x11`，设备到电脑 `0x21` |
| 命令 | 1 | 命令编号 |
| 数据长度 | 2 | 小端 `uint16` |
| 数据 | 可变 | 命令内容 |
| 校验 | 1 | 从帧头到数据末尾逐字节相加，保留低 8 位 |
| 帧尾 | 1 | 固定 `0x16` |

USB 仍使用 `VID=0x0483`、`PID=0x5750` 和 1024 字节 HID report。固件升级仍使用 `0x05`、原来的 1010 字节数据分包和逐包 ACK，没有修改。

## `0x19` 整机快照

电脑发送空数据帧。设备返回 72 字节数据，所有多字节整数均为小端格式。

| 数据偏移 | 长度 | 内容 |
| ---: | ---: | --- |
| 0 | 1 | 应用协议主版本 |
| 1 | 1 | 应用协议次版本 |
| 2 | 6 | 固件版本，例如 `M0.52A` |
| 8 | 1 | 马达端口数量，当前为 4 |
| 9 | 1 | 输入端口数量，当前为 4 |
| 10 | 1 | 六个面板按键位图 |
| 11 | 1 | 电量档位 `0..4` |
| 12 | 2 | 电池 ADC 原始值 |
| 14 | 2 | 按旧固件比例换算的电池采样点毫伏值 |
| 16 | 4 | 功能位图 |
| 20 | 4 | 本次开机运行时间，毫秒 |
| 24 | 24 | A-D 马达状态，每口 6 字节 |
| 48 | 24 | 1-4 号输入口状态，每口 6 字节 |

每个马达条目：状态 1 字节、有符号功率 1 字节、有符号测速累计值 4 字节。状态 `0/1/2` 分别表示自由滑行、驱动和主动刹车。

每个输入口条目：连接状态、传感器类型、模式、数值有效标志各 1 字节，随后是 2 字节读数。需要 ADC、接收字节数或校验错误等详细诊断时，继续使用 `0x18`。

功能位图：

- bit 0：固件升级；
- bit 1：通用马达控制；
- bit 2：马达测速；
- bit 3：输入传感器；
- bit 4：电池状态；
- bit 5：面板按键；
- bit 6：马达类型识别；
- bit 7：马达角度/圈数控制；
- bit 8：双电机同步角度控制；
- bit 9：双电机同步持续定速；
- bit 10：毫米直行诊断；
- bit 11：圈/度/秒直行。
- bit 12：EV3 转向值持续移动。
- bit 13：EV3 转向值定量移动。
- bit 14：MicroPython 最小运行时和状态查询。
- bit 15：RAM Python 程序上传、运行、停止和状态查询。

## `0x1A` 马达类型

电脑发送空数据帧时保持 V1.1 的只读行为。V1.3 也可发送 2 字节数据 `[action=1, port=0..3]`，清除指定端口的旧类型并启动静止刷新。刷新要求 A-D 四路均已停止且没有位置、定速或诊断任务。`M0.67A` 起，固件保持 H 桥关闭，先在目标口编码器 pin 6 浮空时采样 pin 5 ADC，再把 pin 6 拉低并第二次采样，最后恢复浮空输入；该过程不发出马达转动命令。`M0.65A` 的 H 桥零差分采样和 `M0.66A` 的 pin 6 高/低采样均未通过 B 口低相位实测。

V1.1-V1.3 设备返回 21 字节数据：结果 1 字节，随后是 A-D 四个 5 字节条目。V1.4 设备返回 53 字节数据：结果 1 字节，随后是 A-D 四个 13 字节条目；每项依次为类型 1 字节，以及常态、pin 6 拉低、pin 5 弱上拉三组“ADC 原始值 2 字节 + 毫伏值 2 字节”。V1.5 返回 57 字节数据，每个 14 字节条目在上述字段后增加 `pin5_pullup_high` 1 字节，`0/1` 分别表示弱上拉时 GPIO 读到低/高。结果 `1` 表示请求接受，`2` 表示当前忙碌或输出未停止，`0` 表示参数错误。类型 `4` 为大型马达，`5` 为中型马达，`0` 为未连接，`0xFF` 为尚未稳定识别。电脑端兼容解析 21、53 和 57 字节回包。

## `0x1B` 角度与圈数控制

所有角度均为有符号小端整数，固件使用 `1 编码器计数 = 1°`。圈数由电脑端换算为 `圈数 × 360°` 后发送。

电脑请求：

| action | 数据长度 | 数据 |
| ---: | ---: | --- |
| `0` 状态 | 2 | action、端口 `0..3` |
| `1` 启动 | 7 | action、端口、目标转速 `10..100`、有符号目标角度 `int32` |
| `2` 停止 | 2 | action、端口 |

单次目标限制为 `-3600..3600°` 且不能为 0。启动前端口必须已稳定识别为大型或中型马达；短行程可能自动降低实际目标转速。

设备返回 22 字节数据：

| 数据偏移 | 长度 | 内容 |
| ---: | ---: | --- |
| 0 | 1 | 结果：`1` 接受、`2` 忙碌或条件不满足、`0` 参数错误 |
| 1 | 1 | 端口 `0..3` |
| 2 | 1 | 状态：`0` 空闲、`1` 运行、`2` 完成、`3` 超时 |
| 3 | 1 | 马达类型 |
| 4 | 1 | 有符号有效目标转速 |
| 5 | 1 | 有符号实测转速 |
| 6 | 4 | 启动编码器计数 |
| 10 | 4 | 目标编码器计数 |
| 14 | 4 | 当前编码器计数 |
| 18 | 4 | 剩余误差，目标减当前 |

到位后固件短暂主动刹车，再自动回到自由滑行。超时会直接关闭输出；升级和关机路径仍会强制停止全部马达。

## `0x1C` 持续闭环定速

电脑请求：

| action | 数据长度 | 数据 |
| ---: | ---: | --- |
| `0` 状态 | 2 | action、端口 `0..3` |
| `1` 启动 | 3 | action、端口、有符号目标转速 `int8` |
| `2` 自由滑行停止 | 2 | action、端口 |
| `3` 主动刹车停止 | 2 | action、端口 |

目标转速只接受 `-100..-10` 或 `10..100`。启动前指定端口必须稳定识别为大型或中型马达，且不得有位置、定速、类型刷新或诊断任务。固件持续运行闭环，直到收到明确停止、开始升级或进入关机路径。

设备返回 12 字节数据：

| 数据偏移 | 长度 | 内容 |
| ---: | ---: | --- |
| 0 | 1 | 结果：`1` 接受、`2` 忙碌或条件不满足、`0` 参数错误 |
| 1 | 1 | 端口 `0..3` |
| 2 | 1 | 定速状态：`0` 空闲、`1` 运行 |
| 3 | 1 | 输出状态：`0` 自由滑行、`1` 驱动、`2` 主动刹车 |
| 4 | 1 | 马达类型 |
| 5 | 1 | 有符号目标转速 |
| 6 | 1 | 有符号实测转速 |
| 7 | 1 | 有符号当前输出功率 |
| 8 | 4 | 当前编码器累计计数 |

## `0x1D` 双电机同步角度

电脑请求：

| action | 数据长度 | 数据 |
| ---: | ---: | --- |
| `0` 状态 | 1 | action |
| `1` 启动 | 12 | action、左端口、右端口、速度 `10..100`、左目标角度 `int32`、右目标角度 `int32` |
| `2` 停止 | 1 | action |

两个目标角度范围均为 `-3600..3600°` 且不能为 0；符号可独立，用于同向或反向运行。`M0.86A` 起绝对值可以不同，固件按目标比例设置基础速度，并把两侧进度投影到较长目标后计算等效同步误差。系统同时只允许一组双电机任务。双电机任务不设自动时间上限，受阻后不会因等待过久自行结束；永久受阻必须由用户显式停止。

设备返回 29 字节数据：结果、状态、左右端口各 1 字节；随后依次为左右目标角度、左右实际角度、当前同步误差和最大同步误差共 6 个 `int32`；最后为有符号 C API 错误码 1 字节。状态 `0/1/2/3` 分别表示空闲、运行、完成和故障。

## `0x1E` 双电机同步持续定速

电脑请求：

| action | 数据长度 | 数据 |
| ---: | ---: | --- |
| `0` 状态 | 1 | action |
| `1` 启动 | 5 | action、左端口、右端口、左目标转速 `int8`、右目标转速 `int8` |
| `2` 自由滑行停止 | 1 | action |
| `3` 主动刹车停止 | 1 | action |

左右目标速度可独立设置，绝对值均为 `10..100%`，方向符号也可独立。`M0.87A` 起固件把两侧编码器进度投影到较大目标速度的等效尺度后计算同步误差，并按目标比例换算同伴限速和纠偏量；例如 `40%/20%` 的正常行程比例为 `2:1`。固件不设自动超时，任务保持到显式停止、升级或关机。速度 `0` 和绝对值低于 `10%` 的闭环目标暂不支持。

设备返回 27 字节数据：结果、状态、左右端口、左右目标转速、左右实测转速和左右输出功率各 1 字节；随后为左右累计角度、当前同步误差和最大同步误差共 4 个 `int32`；最后为有符号 C API 错误码 1 字节。两路目标速度不等时，同步误差是投影到较大目标速度后的等效角度差，左右累计角度仍为各自真实编码器角度。

## `0x1F` 毫米直行诊断

电脑请求：

| action | 数据长度 | 数据 |
| ---: | ---: | --- |
| `0` 状态 | 1 | action |
| `1` 启动 | 13 | action、左端口、右端口、轮径 `uint16`、轮距 `uint16`、距离 `int32`、速度、停止方式 |
| `2` 停止 | 1 | action |

轮径、轮距和距离使用毫米；当前只支持停止方式 `0` 自由滑行。固件用轮径把有符号距离换算为两个相同的轮子目标角度，换算结果必须落在 `-3600..3600°`。轮距保存在底盘配置中，直行计算暂不使用。该命令已通过链路验证，但最终软件界面不显示距离参数。

设备返回 37 字节数据：结果、状态和左右端口各 1 字节；随后依次为目标距离、实际距离、左右目标角度、左右实际角度、当前同步误差和最大同步误差共 8 个 `int32`；最后为有符号 C API 错误码 1 字节。

## `0x20` 圈/度/秒直行

电脑请求：

| action | 数据长度 | 数据 |
| ---: | ---: | --- |
| `0` 状态 | 1 | action |
| `1` 启动 | 10 | action、左端口、右端口、目标模式、目标值 `int32`、速度、停止方式 |
| `2` 停止 | 1 | action |

目标模式 `0` 为角度，范围 `-3600..3600°`；圈数不另占协议模式，由上位机按 `1 圈 = 360°` 换算后使用模式 0。目标模式 `1` 为时间，单位毫秒，范围 `-600000..600000 ms`。目标值不能为 0，正负号表示两个马达的运行方向，速度独立设置为 `10..100%`。角度模式当前只支持停止方式 `0` 自由滑行；时间模式支持 `0` 自由滑行和 `1` 主动刹车。时间模式由固件 `board_motor_tick()` 内部计时并自动停止，不依赖 USB 主机按时发送命令。

设备返回 31 字节数据：结果、状态、目标模式、左右端口和有符号目标速度各 1 字节；随后依次为目标值、实际进度、左右实际角度、当前同步误差和最大同步误差共 6 个 `int32`；最后为有符号 C API 错误码 1 字节。角度模式的目标值和进度单位为度，时间模式为毫秒；左右实际值始终为编码器角度。

## `0x21` EV3 持续转向

电脑请求：

| action | 数据长度 | 数据 |
| ---: | ---: | --- |
| `0` 状态 | 1 | action |
| `1` 启动 | 5 | action、左端口、右端口、转向值 `int8`、移动速度 `int8` |
| `2` 自由滑行停止 | 1 | action |
| `3` 主动刹车停止 | 1 | action |

转向值范围为 `-100..100`，移动速度范围为 `-100..100` 且不能为 0。换算遵循 EV3 Classroom 1.5.2 的移动积木语义：转向绝对值为 100 时，原始左右值为 `steering/-steering`；其他值为截断到 `-100..100` 的 `100+steering` 与 `100-steering`，再分别乘以移动速度并除以 100。速度 80 时，转向 `0/+50/-50/+100` 分别得到 `80/80`、`80/40`、`40/80`、`80/-80`。该命令不使用轮径、轮距或机身角度。

持续转向复用 `0x1E` 的双电机比例闭环和 27 字节状态回包，但回包命令号为 `0x21`。固件不设自动超时，任务保持到显式停止、升级或关机。当前闭环要求换算后的左右速度绝对值均为 `10..100%`；低于 10% 或等于 0 的结果返回不支持，原地旋转应使用精确的 `±100` 转向值。

## `0x22` EV3 定量转向

电脑请求：

| action | 数据长度 | 数据 |
| ---: | ---: | --- |
| `0` 状态 | 1 | action |
| `1` 启动 | 11 | action、左端口、右端口、目标模式、转向值 `int8`、移动速度 `int8`、正目标值 `int32`、停止方式 |
| `2` 自由滑行停止 | 1 | action |

转向值和左右速度换算与 `0x21` 完全相同。目标模式 `0` 为外侧或较快一侧车轮的角度，范围 `1..3600°`；圈数由上位机按 `1 圈 = 360°` 换算。固件根据左右有效速度比例生成两个有符号目标角度，例如转向 `+50`、速度 `+80`、目标 `720°` 会生成左/右 `+720°/+360°`；速度改为 `-80` 时生成 `-720°/-360°`；转向 `+100` 时生成 `+720°/-720°`。角度模式当前只支持停止方式 `0` 自由滑行。

目标模式 `1` 为时间，范围 `1..600000 ms`。左右马达使用换算后的有符号速度，由固件内部计时，到时自动按停止方式 `0` 自由滑行或 `1` 主动刹车，不依赖电脑按时发送停止。两种模式都要求换算后的左右速度绝对值均为 `10..100%`。

设备返回 42 字节数据：结果、状态、模式、左右端口、转向值、请求移动速度、左右有效速度各 1 字节；随后依次为目标值、实际进度、左右目标角度、左右实际角度、当前同步误差和最大同步误差共 8 个 `int32`；最后为有符号 C API 错误码 1 字节。角度模式的进度是较长目标侧已经运行的绝对角度，时间模式的进度单位为毫秒；左右实际角度始终保留方向符号。

## `0x23` MicroPython 运行状态

电脑发送空数据帧。设备返回 28 字节只读状态，不执行用户脚本、不改变传感器模式，也不启动马达。

| 数据偏移 | 长度 | 内容 |
| ---: | ---: | --- |
| 0 | 1 | 状态结构版本，当前为 `1` |
| 1 | 1 | 状态：`0` 未启动、`1` 启动中、`2` 通过、`3` 脚本异常、`4` 自检值错误 |
| 2 | 1 | 标志位 |
| 3 | 1 | 保留，当前为 `0` |
| 4 | 4 | Python 堆总字节数 |
| 8 | 4 | Python 堆已用字节数 |
| 12 | 4 | Python 堆剩余字节数 |
| 16 | 4 | 启动及自检耗时，毫秒 |
| 20 | 4 | 本次开机最大 GC 停顿，微秒 |
| 24 | 2 | GC 次数 |
| 26 | 2 | 启动自检值；M0.94A 成功时为 `96` |

标志位 bit 0-4 依次表示解释器已初始化、自检脚本完成、捕获到脚本异常、至少执行过一次 GC、异常清理已调用。M0.94A 正常启动后状态应为 `2`，并同时具有 bit 0、bit 1 和 bit 3。

## `0x24` RAM Python 程序

源码只保存在 RAM，设备重启后消失。单次源码长度为 `1..8192` 字节，不允许 NUL；电脑必须按连续偏移分块发送，并用 CRC32 确认完整性。该通道与 `0x05` 固件升级完全独立。

请求的第一个数据字节为动作：

| 动作 | 后续数据 | 说明 |
| ---: | --- | --- |
| `0` | 无 | 查询状态 |
| `1` | 源码长度 `uint16`、CRC32 `uint32` | 开始上传并清空旧状态 |
| `2` | 偏移 `uint16`、`1..1000` 字节源码 | 顺序写入一块源码 |
| `3` | 硬超时毫秒 `uint32` | 运行已校验源码；范围 `100..10000 ms` |
| `4` | 无 | 主动停止正在排队或运行的程序 |
| `5` | 无 | 清除未运行的 RAM 程序和状态 |

每个动作都返回相同的 32 字节状态：

| 数据偏移 | 长度 | 内容 |
| ---: | ---: | --- |
| 0 | 1 | 状态结构版本，当前为 `1` |
| 1 | 1 | 请求结果：`0` 拒绝、`1` 成功、`2` 忙 |
| 2 | 1 | 程序状态 |
| 3 | 1 | 错误 |
| 4 | 1 | 标志位 |
| 5 | 1 | 保留，当前为 `0` |
| 6 | 2 | 期望源码长度 |
| 8 | 2 | 已接收源码长度 |
| 10 | 2 | 完整运行次数 |
| 12 | 4 | 期望 CRC32 |
| 16 | 4 | 实际 CRC32 |
| 20 | 4 | 本次运行耗时，毫秒 |
| 24 | 4 | 本次硬超时，毫秒 |
| 28 | 4 | 脚本测试结果，有符号 `int32` |

程序状态为：`0` 空、`1` 接收中、`2` 就绪、`3` 已排队、`4` 运行中、`5` 完成、`6` Python 异常、`7` 主动停止、`8` 超时、`9` 无效。错误为：`0` 无、`1` 请求无效、`2` CRC 错误、`3` Python 异常、`4` 主动停止、`5` 超时、`6` 内部错误。

标志位 bit 0-3 依次表示源码有效、脚本设置了测试结果、已经调用统一清理、硬超时仍处于启用状态。M0.96A 起，运行期间 VM 每 1 ms 维持 USB 轮询，但只接受 `0x24` 命令；主动停止、硬超时和 Python 异常都会停止全部马达、调用 `est_system_cleanup()` 并重启四路传感器。传感器在清理后可能短暂显示同步中，通常约 2 秒恢复。

## 电池说明

电池采样使用 V5 主板确认的 `PF3 / ADC3 channel 9`。电量档位沿用旧 EST APP 的充电电池阈值。返回的 `battery_sample_mv` 是分压采样点数值，不是电池组端子上的实际电压；上位机应优先显示 `battery_level`，在实物校准完成前不要把采样值直接标成电池电压。
